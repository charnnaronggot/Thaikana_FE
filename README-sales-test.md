# Railway Sales test frontend

Production build for all local roles: `npm run build:workspace`, or `docker build --build-arg BUILD_CONFIGURATION=production,workspace -t thaikana-workspace:local .`. With the existing local API ready on port 5248 and port 4240 free, run `npm run preview`. This starts Nginx bound only to `127.0.0.1:4240`; it does not deploy or initialize a database. Stop it with `docker stop thaikana-workspace-local`, and remove that named container before restarting. The Sales-only production default remains available. No Railway configuration is changed by this workflow.

Set `LOCAL_PRODUCTION_CHECK=true` for the additional Playwright security-header, session refresh and PWA online-only checks. Mutation interception tests explicitly block Service Workers and deny unhandled non-auth writes. An initial production test exposed that page-level interception alone could be bypassed by the service worker; that test created one WO in the shared test DB, retained with its audit history. Subsequent mutation checks use a displayed planning-status fixture and intercepted commands, without requiring pending shared records.

Removed the unused `serve` preview dependency and its vulnerable `compression` tree; Docker/Nginx now serves previews. `npm audit` reports zero known vulnerabilities as of 2026-10-16; this is dependency advisory coverage, not a complete security assessment. New CI runs unit checks, both release configurations and isolated proxy/DNS regression.

Local full workspace: `ng serve --configuration local --port 4240 --proxy-config ../../.local/sales-proxy.json` enables role-specific landing pages, menus and native API adapters. The private `.local/Start-Thaikana-Local.ps1` launcher uses this configuration. Default/production builds keep Sales-only routes; this local work does not deploy to Railway. Local still connects to the authorized shared Railway test DB/S3 through the local Backend.

Native pages provide current data/details for Design, Planning, Production/Station, Inventory, QC, Delivery, users and overview. Planning decision commands use the existing native gateway and idempotent mutation handling. Other native write workflows are explicitly marked unavailable; old UI contracts are not reused against incompatible endpoints. Finance remains unavailable because Backend main has no corresponding API/role. This is role-navigation and API-read integration, not completion of every business milestone. Station execution also remains gated pending reconciliation of Backend policy with the latest handoff (multiple active WOs, verification lifetime and no Machine).

Local checks: `npx playwright test --config playwright.local.config.ts` with private `LOCAL_TEST_PASSWORD` and optional `LOCAL_TEST_ARTIFACTS`. Role cases exercise all 14 seeded accounts; workflow cases check server Station/Viewer denial, responsive Station layout and simulated uncertain Planning command retries without shared business-data mutations.

Quotation forms separate payment terms, delivery lead time, delivery location, shipping charges and customer-facing remarks. Company VAT is read-only for Sales; MBO product codes are optional. Existing products show their base unit; bank details are opt-in. New PDFs use Backend quotation template v2, while previously issued PDFs retain their original bytes. Run `quotation-form.spec.ts` in the Sales Playwright configuration for responsive form checks without saving test records.

Login encrypts both username and password with Web Crypto AES-256-GCM and a Backend RSA-OAEP/SHA-256 public key before posting to `/auth/login/encrypted`. Each attempt obtains a fresh two-minute, single-use challenge from `/auth/login-challenge`. There is no plaintext fallback. HTTPS (or localhost for local development) is required. Refresh-cookie and in-memory access-token behavior are retained. An already-open old client must reload after this contract change.

Select GitHub branch `main`, repository root `/`, Dockerfile builder. Sales now targets the native Backend main (`ThaikanaDbContext`) through `/api/v1/sales-ui/*`, while authentication uses the unchanged `/api/v1/auth/*` endpoints. The frontend includes Sales, customer register and authorized company settings; other business pages are not routed. Native permissions are mapped for UI display only; server access/scope checks remain authoritative. Customer maintenance follows native `master.manage` permissions, not an automatic Sales grant.

Set `API_UPSTREAM=http://YOUR-BACKEND-SERVICE.railway.internal:8080` with no trailing slash or path when both services share the Railway environment. The backend must listen on `[::]` for private IPv6 connectivity. Nginx uses local DNS resolvers and refreshes upstream addresses after deployments without restarting. Nginx proxies `/api/v1` while the browser uses the frontend origin, preserving secure refresh cookies. Railway supplies `PORT`; `/health` is the frontend healthcheck. Configure the exact frontend HTTPS origin in the backend's `Cors__AllowedOrigins__0`.

Proxy regression: build the production image as `thaikana-sales-frontend:test`, then run `node tests/deploy-proxy.smoke.cjs`. This checks authenticated POST routing, query strings, forwarded protocol, response cookies and DNS replacement against isolated Docker fixtures. Set `PROXY_TEST_IMAGE` to use another locally built image.

Connect the native Backend test service and database first, then generate a frontend domain and set the matching CORS origin. Use an existing native account or configured bootstrap administrator, complete its password change, configure company/VAT/terms in Settings and register fictitious customers. Existing products come from the published native catalogue; Made By Order units are loaded from the UOM master. PDF preparation precedes Send; acceptance collects PO, evidence and an explicit delivery due date. PDF jobs use native background generation, polling and retry.

Git push alone does not select Railway's watched branch, create service variables, assign domains or copy data. Source from earlier demo milestones remains in repository history, but production builds include only the Sales routes and their dependencies.

Browser checks: set `SALES_TEST_URL`, `SALES_TEST_USERNAME`, `SALES_TEST_PASSWORD` privately, then run `npx playwright test --config playwright.sales.config.ts`. Use an initialized native test database with company settings, an active customer and a shared published product. Checks cover real login, the Sales presentation namespace's isolation, restricted navigation, mixed draft at four sizes, PDF → Send → PO → Order. Native Backend main's other business APIs are intentionally retained. Existing preview-only `serve` development dependency has an npm audit advisory; it is not installed in the final Nginx runtime image.
